# WarCanvas 事件总线和命令总线

## 概述
在WarCanvas项目中，我们采用了两种不同的通信机制来处理系统间的交互：事件总线（EventBus）和命令总线（CommandBus）。这两种机制各司其职，共同构成了项目的通信架构，实现了系统间的解耦和高效协作。

## 事件总线（EventBus）

### 基本概念
事件总线是一种基于信号的通信机制，用于系统间的松耦合通信。它只通过配置signal进行系统间通信，不涉及游戏（对局）内的具体操作，仅用于通知事件发生，主要用于UI的逻辑传递。

### 设计原理
事件总线采用观察者模式，允许系统订阅和发布事件，而无需直接引用彼此。这种设计实现了系统间的解耦，提高了代码的可维护性和可扩展性。

### 主要特点
1. **单向通信**：事件从发布者流向订阅者，不期望返回值
2. **多对多关系**：一个事件可以有多个订阅者，一个发布者可以发布多种事件
3. **松耦合**：发布者和订阅者之间没有直接依赖关系

### 使用场景
1. **UI状态更新**：通知UI组件游戏状态的变化
2. **系统通知**：广播系统级事件，如游戏开始、暂停、结束等
3. **状态变化通知**：通知相关系统游戏状态的变化
4. **玩家行为反馈**：提供玩家行为的视觉和音频反馈

### 实现方式
```gdscript
# EventBus.gd
extends Node

# 定义信号
signal resource_changed(resource_type, amount)
signal building_completed(building_id)
signal unit_selected(unit)
signal turn_started(player_id)

# 发布事件
func emit_resource_changed(resource_type, amount):
    resource_changed.emit(resource_type, amount)

# 订阅事件
func _ready():
    EventBus.resource_changed.connect(_on_resource_changed)

func _on_resource_changed(resource_type, amount):
    # 处理资源变化事件
    update_ui(resource_type, amount)
```

### 事件类型
1. **资源事件**：资源变化 更新ui
2. **UI事件**：按钮点击、菜单打开/关闭等
3. **游戏事件**：回合开始/结束、胜利/失败等

### 最佳实践
1. **事件命名**：使用清晰、一致的命名约定
2. **参数设计**：保持事件参数简洁明了
3. **避免循环**：防止事件处理过程中触发相同类型的事件
4. **性能考虑**：避免在高频更新的地方使用事件总线

## 命令总线（CommandBus）

### 基本概念
命令总线通过规范的命令系统处理游戏（对局）内的具体操作，用于完成玩家执行具体的任务。玩家实际上的所有影响游戏的操作都是由命令（Command）来完成的。

### 设计原理
命令总线采用命令模式，将请求封装为对象，从而允许用不同的请求对客户进行参数化、排队或记录请求日志，以及将来的支持可撤销的操作。

### 主要特点
1. **封装操作**：每个命令封装了一个具体的游戏操作
2. **可撤销性**：命令可以设计为可撤销的，支持撤销/重做功能
3. **历史记录**：可以记录命令历史，用于调试和回放

### 使用场景
1. **玩家操作**：移动单位、建造建筑、采集资源等
2. **AI决策**：AI执行的所有游戏操作

### 实现方式
```gdscript
# Command.gd
class_name Command
extends RefCounted

var executor: Node  # 执行命令的对象

func _init(executor: Node):
    self.executor = executor

# 执行命令
func execute():
    pass

# 撤销命令
func undo():
    pass

# CommandBus.gd
extends Node

var command_queue: Array[Command] = []

func execute_command(command: Command):
    command.execute()
    command_queue.append(command)

# MoveCommand.gd
class_name MoveCommand
extends Command

var unit: Unit
var target_position: Vector2

func _init(unit: Unit, target_position: Vector2):
    super(unit)
    self.unit = unit
    self.target_position = target_position

func execute():
    var old_position = unit.position
    unit.move_to(target_position)
    return old_position

func undo():
    unit.move_to(previous_position)
```

### 命令类型
1. **单位命令**：移动、攻击、防御等
2. **建筑命令**：建造、升级、拆除等
3. **资源命令**：采集、加工、交易等
4. **系统命令**：结束回合等
5. **AI命令**：AI决策执行以上的所有命令

### 命令流程
1. **命令创建**：根据玩家输入或AI决策创建命令对象
2. **命令验证**：验证命令的合法性（资源足够、目标有效等）
3. **命令执行**：执行命令的具体操作
4. **状态更新**：更新游戏状态
5. **历史记录**：将命令添加到历史记录中

### 最佳实践
1. **单一职责**：每个命令只负责一个具体操作
2. **验证前置**：在执行前充分验证命令的合法性
3. **原子操作**：确保命令的执行是原子的，要么全部成功，要么全部失败
4. **错误处理**：提供清晰的错误信息和处理机制

## 两种总线的协作

### 协作模式
事件总线和命令总线在项目中协同工作，形成完整的通信架构：

1. **输入处理**：
   - 玩家输入 → 创建命令 → CommandBus执行命令 → EventBus通知状态变化 → UI更新

2. **AI决策**：
   - AI分析 → 创建命令 → CommandBus执行命令 → EventBus通知状态变化 → 其他系统响应

### 设计原则
1. **职责分离**：事件总线负责通知，命令总线负责执行
2. **数据流向**：事件总线用于数据流动，命令总线用于操作执行
3. **系统边界**：明确两种总线的使用边界，避免混用

## 性能优化

### EventBus优化
1. **事件合并**：合并频繁发生的小事件
2. **延迟处理**：对非关键事件进行延迟处理
3. **订阅管理**：及时取消不再需要的订阅

### CommandBus优化
1. **批量执行**：将多个相关命令批量执行
2. **命令合并**：合并可以合并的连续命令
3. **异步执行**：对非关键命令进行异步执行

## 调试与测试

### 调试工具
1. **事件追踪**：记录事件的发布和订阅情况
2. **命令历史**：查看命令的执行历史和结果
3. **性能分析**：分析两种总线的性能表现

### 测试策略
1. **单元测试**：测试单个事件和命令的功能
2. **集成测试**：测试系统间的交互
3. **性能测试**：测试高负载下的表现

## 总结
事件总线和命令总线是WarCanvas项目架构的核心组成部分，它们共同实现了系统间的解耦和高效协作。事件总线负责状态通知和UI更新，命令总线负责游戏操作的执行。通过合理使用这两种通信机制，项目实现了清晰的架构分层和良好的可维护性。
